# Еквівалентні (взаємозамінні) ролі

Правило користувача від 30.09.2026. Читати, коли тендер просить спеціалістів певних ролей, при складанні команди (аркуш «Команда» чек-листа) і при підготовці CV під тендер.

**Суть.** Багато назв ролей в ІТ означають по суті одну спеціалізацію. Якщо тендер просить роль зі складу групи, ми можемо заявити будь-якого нашого спеціаліста з цієї групи, а в заявці й CV (посада в шапці) писати роль дослівно так, як її назвала ТД.

## 1. Групи

| Група | Ролі, які вважаємо однаковими |
|---|---|
| Розробка | Frontend Developer = Backend Developer = Full Stack Developer = Senior Software Engineer = Software Engineer = Software Developer = Розробник програмного забезпечення = Веб-розробник |
| Керівництво | Project Manager = Керівник проєкту = Delivery Manager = Team Lead |
| Аналітика | Business Analyst (Бізнес-аналітик) = System Analyst (Системний аналітик) = Аналітик вимог |
| Документація | Technical Writer = Технічний письменник = Спеціаліст з технічної документації |
| Тестування | QA Engineer = Test Engineer = QA Manual = QA Automation = Тестувальник = Інженер з тестування |
| DevOps та інфраструктура | DevOps Engineer (DevOps-інженер) = SRE = Системний адміністратор = Інженер з інфраструктури |
| Дизайн | UI/UX Designer = Product Designer = Web Designer = UX/UI-дизайнер |
| Безпека | Інженер з кібербезпеки = Security Specialist = Спеціаліст із захисту інформації |
| Архітектура | Software Architect (окрема роль: замінюється лише на Team Lead, див. п. 2) |

## 2. Односпрямовані зв'язки між групами

- **Business Analyst → Technical Writer.** Бізнес-аналітика можна заявити технічним письменником (за вказівкою користувача). У зворотний бік (технічний письменник → аналітик) зв'язку немає.
- **Team Lead ↔ Software Architect.** Team Lead може бути заявлений як Software Architect і навпаки. Зв'язок стосується лише цієї пари ролей і не поширюється на решту групи «Керівництво» (Project Manager, Delivery Manager архітекторами не стають).
- Інших зв'язків між групами немає.

## 3. Як застосовує ШІ

1. Кандидатів шукаємо за колонками «Група ролей» і «Ролі для тендерів» у `cv/00 Реєстр спеціалістів.md` (не за всім текстом резюме).
2. Еквівалентність застосовуємо автоматично в межах групи, без спливаючого питання (вибір користувача від 30.09.2026). Роль заявляємо дослівно з ТД, у підсумку по роботі одним реченням пишемо, де замінено роль (напр.: «для ролі Full Stack Developer заявлено Іванова І. (Backend Developer) за правилом еквівалентності»).
3. Еквівалентність міняє лише назву ролі. Вона не скасовує інших вимог ТД, які перевіряємо окремо: рівень (Junior/Middle/Senior) і мінімальний стаж у ролі, освіту, сертифікати й допуски, конкретні технології. Стаж беремо з реєстру («Досвід у заявлюваній ролі»); якщо ТД вимагає стаж саме на посаді з іншою назвою, це йде в перелік прогалин і ризиків.
4. Якщо ТД прямо забороняє заміну ролей, дає своє визначення ролі з окремими обов'язками чи вимагає підтвердити посаду наказом з такою самою назвою, еквівалентність не застосовуємо й повідомляємо користувача.
5. Групи, яких тут немає (наприклад, мобільний розробник, Data Engineer, архітектор поза зв'язком із Team Lead), вважаємо окремими ролями. Якщо тендер їх просить, ШІ питає користувача.
6. Нові групи чи зв'язки користувач додає в цей файл.
